# collaboration-workflow.md — 协作工作流

## 任务隔离（防上下文污染）

不在同一长对话里既做架构设计、又写实现、又修 bug、又写报告。推荐流程：

```
1. 规划会话：读 AGENTS.md + 相关 docs → 输出 proposal / Spec
2. 用户审批
3. 执行会话（新窗口）：只注入 AGENTS.md + docs/ai/module.md + 当前子任务相关文件
4. 子任务完成 → 关闭会话；下一子任务再开新会话
```

经验阈值：单对话纠缠超 ~10 轮仍不清晰 → 拆分任务、新建会话。

## 新会话最小上下文包

| 任务类型 | 必读 |
|---|---|
| 任何新会话 | AGENTS.md |
| 写/改代码 | docs/ai/module.md + docs/pitfalls.md |
| 改 API/数据模型 | docs/api-contracts.md + docs/data-models.md |
| 交付前 | docs/agents-maintenance.md + AGENTS.md §8 |
| 大改动 | docs/spec-template.md |

## 实现前影响面分析（动手前输出）

1. 涉及哪些现有模块？（查 module.md）
2. 是否新增配置/接口字段？需同步哪些读写路径？
3. 是否破坏红线（AGENTS.md §2）？
4. 是否需要更新 pitfalls / README？
5. 对照 agents-maintenance 触发表，列出本任务将更新的全部文档路径

## 实现后文档同步（交付前必做）

1. 按影响面分析第 5 条逐项更新
2. 对照 AGENTS.md §8 检查清单勾选
3. 回复中列出已同步的文档路径

## Spec 驱动（大改动必做）

**大改动判定**（满足任一）：触及 ≥3 个源码文件；改数据流/数据模型；新增配置分组；引入新第三方依赖；新增档案产物类型。

流程：先写 Spec（docs/spec-template.md）→ 用户审批 → 逐条实现，禁止「边想边堆」。

## 计划文件

多文件或架构决策：先写/更新 `PLAN.md`，用户确认后再实现。用户可随时手改 PLAN.md，AI 以其为任务依据。

## 高成本操作授权

本项目的高成本操作：生产部署与回滚、生产数据库迁移执行、批量删除数据、备份上传外部存储、长时间运行的任务。

| 角色 | 职责 |
|---|---|
| AI | 代码准备、配置落档、smoke test、给出可复制执行命令 |
| 用户 | **亲自**执行完整高成本操作 |

规则：
- AI 不得私自执行高成本操作；未授权结果不作正式产物，并在下一轮说明
- smoke test（极小规模验证）可由 AI 执行，须标注「smoke test，非正式运行」
- Windows 开发机上的 `pnpm dev`、`prisma migrate dev`（本地 dev db）、单元测试属于日常操作，无需授权

## 人机分工

| 事项 | AI | 用户 |
|---|---|---|
| 读文档、改代码、smoke test、文档同步 | ✅ | — |
| 高成本操作 | 只给命令 | ✅ 亲自执行 |
| 大改动 Spec、方案落档 | 起草 | ✅ 确认后执行 |
| 需求不清 | 提问、复述 | ✅ 澄清 |
| 计划方向（PLAN.md） | 辅助 | ✅ 主责 |
| 腾讯云 OSS key 与用法 | — | ✅ 提供 |
