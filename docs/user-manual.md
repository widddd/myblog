# 站长手册（高级用途与注意事项）

面向已经会发文、审评论的站长。登录、写文章、瞬间、搜索、主题切换等基本操作不在这里。

程序内部备份包、更新包文件名带 `myblog-`，那是程序标识，**不是**访客看到的站点名。

完整安装步骤见根目录 [README.md](../README.md) 与 [`main/INSTALL.md`](../main/INSTALL.md)。

---

## 开箱与账号

- 空库第一次打开站点会进 **`/admin/setup`（创建站点）**。必须自己填**站点名称**（导航、页脚、首页大标题、浏览器标题都用这一项）。没有默认名 MyBlog。
- 站点地址、首页副标题可选；之后可在「设置」里改。创建成功会把「站点开始运行时间」写成当时，首页运行时间模块才有起点；不想显示就到设置里清空。
- 备份口令与登录密码不能相同，**只能设一次，设完不能改**。口令用来合成备份加密密钥，不是登录密码。
- Linux 无浏览器时用 `pnpm setup`，问的是同一套字段。不要在生产跑 `pnpm db:seed`（会灌演示文章）。
- 半钥文件在 `main/data/backup-host-secret.json`：**不要打进备份、不要提交 git、不要放进更新包**。丢了这个文件，加密备份只能靠当时设的口令在停服后 `pnpm restore --passphrase` 解开。
- 忘记管理员密码：可在管理员清理后打开 `/admin/setup` 直接重建管理员；已有半钥时页面只要求用户名和新密码，站点配置与备份口令保持不变。无浏览器时停服后在 `main/` 执行 `pnpm setup` 也可补建管理员。半钥若还在，只会补管理员，**不会**让你改备份口令。
- 创建页和登录一样有 CSRF 与按 IP 限速。已经有管理员后再打开创建页会回到登录。

## 首页模块

- 改首页只走后台「模块管理」+「首页管理」，不要去改程序源码里的首页文件。
- 「首页管理」里电脑 / 手机是**两套几何**，保存时一次写入。文案配置共用。电脑可以把多个模块堆进同一格（右侧那列小卡片就是这样来的）；手机不并格。
- 「模块管理」里自定义模块的 HTML / CSS / JS **直接注入前台首页，不过滤**。等于你可以 XSS 自己的站。只贴自己写得懂的代码。CSS 默认只作用于该模块，勾成全站会影响到整页。
- 这条注入路不会进评论或文章正文；那两处仍然消毒 / 纯文本。
- 运行时间只看设置里的「站点开始运行时间」。空着则前台不渲染，不要指望改首页文件来显示。

## 媒体与腾讯云 COS

- 密钥只填后台「设置」，不要写进仓库、不要打进更新包。
- 写文章时图片先落本机；点**发布**才生成一级缩略图并上 COS。草稿阶段 COS 上还没有这些图。
- 超过约 10MB 的图片会先警告，再按原格式压到限额以下当原图，不会直接打回。
- 一级缩略图本地与 COS 双写；**二级缩略图只在本机**（给首页瞬间瀑布用），不会写进瞬间 JSON，也不上 COS。
- 媒体库删除**默认连 COS 一起删**。下拉可改成只删本地。关联了文章仍可删，不会用 409 卡死，面板会警告。
- 本机媒体缓存有上限（默认 512MB），超了会删最早的本地副本；云上若没有副本则不删，以免变成唯一一份丢失。
- COS 桶应只给本站用。桶里的对象和本机目录树用同一套 key。
- **点开原图（灯箱）走 COS 直链，不经过你的服务器**——原图常有 3–5MB，走服务器等于把你的机器出网带宽当瓶颈（实测差 8 倍）。要让灯箱的**进度环**正常工作，在 COS 桶的「跨域访问 CORS」里加一条：来源 `https://你的域名`、方法 `GET, HEAD`、**暴露响应头 `Content-Length`**。没配也能看图，只是没有进度（会退回同源代理，慢一些）。
- 占用数字要在设置里点「扫描本机占用」才统计一次，打开设置页不会自动扫。

## 瞬间可见范围（可见期与分组）

在后台**发瞬间的发布区**里配置：「瞬间」页（或概览页的「快速发瞬间」卡，同一个发布界面）→ 点底栏的**可见范围** → 弹卡底部**「详细设置」** → 右侧抽屉里就是「全局可见期」与「可见范围组」两块。全部可视化，不需要改源码或环境变量。

- **默认永久公开**（全局可见期 = 0），不设就等于没这个功能：升级后前台输出与之前完全一致。
- **全局可见期**是整站天花板。改成 30 天，就是"发布满 30 天的瞬间不再对外展示"；后台会预告"此刻起算，只有发布在 X 之后的瞬间可见"（保存后立即生效，老瞬间一起按新规则算）。
- **可见范围组**（如「三天可见组」= 3 天）是发瞬间时能直接选的档位，逐条瞬间可选，也可以「跟随全局可见期」。
- **叠加规则只有一条：实际生效 = 更短的那个。** 全局 7 天 + 一年组，实际还是 7 天；全局永久 + 3 天组，就是 3 天。组比全局长时，列表里会标「受全局 N 天限制」——这是设计如此，不是没生效。
- **过期后半公开面按"不存在"处理**：首页瞬间、瞬间页、点赞、评论（含新提交评论）都当它没有，点赞/评论请求返回 404。**内容本身没删**：后台仍保留正文、评论与点赞，列表带「已过期 · 前台已隐藏」徽章、到期时刻与剩余时间，并可随时改可见范围（改短立刻隐藏，改回全局就重新按全局算）。
- **删除组不会删瞬间**：用它的瞬间回落到全局规则。后台会在删除前先告诉你「影响几条、之后按什么规则显示」，看清楚再删。
- **三个入口**：① 后台「瞬间」页的发布区（输入框 + 图片按钮 + 可见范围，详细设置走右侧抽屉）；② **概览页的「快速发瞬间」卡**——同一个发布界面，发完自动刷新概览页，不想要可以在「外观」面板里关掉这张卡；③ 同页下方默认折叠的**「瞬间管理」**——逐条改可见范围或删除，10 条一页。
- **迁移要先跑一次**：这套功能带一张新表与一个新列，需要在 `main/` 下执行 `pnpm prisma migrate dev`（先备份 `main/data/blog.db`），跑完重启一次进程。迁移属高成本操作，请自己执行。

## 静态页面（自建独立页面）

前台地址是 `/{目录}/{地址名}`。目录默认 `pages`，在后台「**静态页面**」页顶部改；每页内容用 HTML / CSS / JS 三栏写，也能直接把现成的静态页贴进来。

- **目录完全自定义，但冲突是硬拦的。** `posts`、`admin`、`api`、`robots.txt` 这些站内已有地址既不能当目录也不能当地址名——后台会直接告诉你跟谁冲突。原因：静态页在 Next 的路由里优先级**最低**，这些地址永远轮不到它处理。所以将来站里新增栏目（例如 `/notes`）时，同名目录下的静态页会**自动让位**，不会把新栏目顶掉。
- **改目录等于把所有页面地址整体搬走**：旧地址立即失效（404），没有 301。保存前后台会先告诉你会影响几个已启用页面。不需要旧链接就别折腾；需要的话自己在新地址页里放个跳转。
- **停用**是逐页开关：停用后前台 404，内容与代码都保留。**删除**不可恢复。
- 页面标题与描述进 `<title>` 和 meta description；启用中的页面自动进 `/sitemap.xml`。
- 这些页面**不套站点的页头页脚**，是独立文档，样式与脚本完全由你掌控。等价于首页自建模块那条「管理员内容面」：只有后台能写、不走正文的消毒管线——**别粘贴来源不明的代码**。
- JS 栏里可以写脚本；HTML 里内联的 `<script>` 不会被浏览器执行（浏览器语义），要跑脚本就写进 JS 栏。脚本里设的定时器/全局监听不会在离开页面时自动清理。
- **迁移要先跑一次**（新表）：在 `main/` 下执行 `pnpm prisma migrate dev`，**执行前先停掉 Node 进程**（dev server 占着库时迁移必然报 `database is locked`，Prisma 不会等锁）。属高成本操作，请自己执行。

## 文章地址与密码文

- 对外地址是 `/posts/{8 位公开 ID}/{链接名}`。改链接名不会改中间那串 ID，旧地址会跳过来。
- 密码文章未解锁时，评论接口不能读也不能写该文。RSS / sitemap 不含密码正文。
- 搜索对密码文只匹配标题。

## 备份与恢复

备份换的是**文章、图片、设置**（`blog.db` + 本地 uploads），**不是**程序源码。

- **自动备份**：设置页「每隔几天自动备份」（默认 3 天）到点自动打一份包，旧包按「最多留几份」滚动清理；想立刻备一份就去「备份」页点「立即备份」。**开启加密后不再自动执行**——加密包要你每次手动输入口令（口令不落盘，定时任务拿不到），这一点在设置页与概览页都会写出来。
- 加密可在「备份」页随时开关。打开加密必须先有备份口令。COS 走 HTTPS 且你没手设时，默认关加密。
- 加密包是拆分密钥：本机半钥 XOR 包内半钥得到 DEK。**只拿走 tar.gz 解不开。** 列表里的指纹、是否加密、版本号可以对照。
- 点「恢复」只写入预约，站点照常用。未到你设的重启时间，启动**不会**覆盖数据库。到点或点「立刻重启」才退出进程、下次启动才覆盖。
- 已经预约了程序更新，就不能再预约恢复（反过来也一样）。先取消一边。
- 生产环境 **pm2 只能 fork 单实例**。不要开 cluster，也不要直接拷 `blog.db` 当备份（要用程序打的包）。
- 换机：带上备份包 + 口令（或把半钥文件拷过去）。应用还在跑时不要在本机当场覆盖库。
- 不要用手解备份 tar，也不要用系统 `tar` 当恢复工具。

命令行恢复必须先停进程，在 `main/` 下：

```powershell
pnpm restore --list
pnpm restore --latest --yes
pnpm restore --file myblog-20260830-120000.tar.gz --yes
pnpm restore --file myblog-20260830-120000.tar.gz --passphrase --yes
```

## 程序更新

更新换的是**程序文件**（`src/`、`prisma/`、`scripts/` 以及包里有的其它顶层目录）。`data/`、`.env`、半钥不动。

- 正规包必须带 `package.json` 和完整 `src/`。打包用**拒绝名单**：不打包 `data/`、`.env*`、`node_modules/`、`.next/`、测试文件。以后在 `main/` 下新增的目录（例如 `plugins/`）会自动进包，不必改白名单。
- 覆盖时：包里出现过的**顶层目录**会按「包里没有的文件删掉」同步。残缺小包可能把 `src/` 掏空，不要拿随便打的包当正式版。
- 不要在正在改代码的这一份 `main/` 上点「立刻重启并更新」。
- 生产构建大约需要几分钟；1GB 内存请先加 swap。构建失败会尝试把旧的 `.next` 拷回来。
- 开发 `pnpm dev` 应用更新时不构建。
- **GitHub**：在「设置」填公开仓库 `owner/repo` 或完整链接，到「更新」页再点「检查更新」。程序**不会**后台轮询。Release 附件文件名必须是 `myblog-update-*.tar.gz`。
- 开发机也可 `pnpm pack:update --git v0.1.2` 按 git 标签导出（只打仓库里 `main/` 那棵树，不含 `docs/`）。
- 发版只换这份 tar.gz，不要改 `install.sh`，不要上传 Windows 的 `node_modules`。

```powershell
cd main
pnpm pack:update
pnpm pack:update --git v0.1.2
pnpm apply-update --file .\myblog-update-xxxx.tar.gz
pm2 restart myblog
```

## 更新页数据清理

`/admin/updates` 的「危险操作 → 清空数据」用于把站点恢复到空内容状态。它只有两个可选范围，且可以同时选：

- **删除数据**：删除文章、分类、标签、笔名清单、瞬间与瞬间可见范围组、评论、媒体记录与文件、本地和 COS 备份、更新暂存，以及备份密钥索引；`Setting`（站点配置，含瞬间的全局可见期）、首页模块/布局、主机半钥和运维日志保留。删除范围以 `lib/data-clear/coverage.ts` 登记的清单为准——新增数据表必须登记，否则 `pnpm test` 会失败（见 pitfalls P-103）。
- **删除管理员账号**：删除全部管理员账号，但不删除文章、媒体或备份。执行后当前会话会失效，进入 `/admin/setup` 后可直接用“重建管理员”表单恢复账号；站点配置与备份口令不变。若使用命令行，请停服后在 `main/` 执行 `pnpm setup`。

勾选范围后必须输入页面显示的精确确认短语，并勾选不可恢复确认。服务器登记后还要等待至少 15 秒，提示窗口底部会显示平滑的红色倒计时进度条；倒计时期间可以点「取消」、关闭按钮、遮罩或按 `Esc` 撤销。倒计时由服务端时间校准，不能通过改浏览器计时绕过等待。令牌只在当前进程内存中保存，应用重启不会自动执行未完成的确认。

选择「删除数据」时，程序会把已配置的 COS 桶视为本站专用，并删除其中列出的本站对象；不要把其他站点或私人文件放在这个桶里。清理会先处理文件，再在 Prisma 事务中删除数据库内容；存储失败会停止后续数据库清理，便于检查配置后重新确认。已有预约恢复时，更新页会先要求到「备份」页取消预约。

## 部署

- 空机：解压更新包 → `bash scripts/install.sh` 一次 → 创建站点（网页或 `pnpm setup`）→ pm2。以后只换包。
- **程序目录不要放在 `/root`（或任何 `$HOME`）**：pm2 的运行时目录 `~/.pm2` 会成为项目目录的一部分，`next build` 读到里面的 socket 会直接失败（Turbopack panic），表现为「更新永远装不上 + 每 60 秒重启一次」。用 `/opt/myblog`；已经装在家目录的，要么把程序搬走，要么把 pm2 家目录挪出去（`pm2 kill` → `rm -rf /root/.pm2` → `PM2_HOME=/var/lib/pm2` 起 pm2，并写进 `.bashrc`、重跑一次 `pm2 startup`）。详见 [pitfalls P-115](pitfalls.md)。
- **生产要有 HTTPS**：应用在 `NODE_ENV=production` 下给登录会话与 CSRF cookie 打 `Secure`，明文 HTTP 访问时浏览器会直接丢掉它们，表现是后台登录一直「CSRF 校验失败」（命令行 `curl` 却一切正常）。没有证书时的临时办法是在 nginx 的代理 location 里摘掉这两个 cookie 的 `Secure`（`proxy_cookie_flags myblog.session nosecure;` 与 `myblog.csrf` 同名一行），上 HTTPS 后删掉。详见 [pitfalls P-116](pitfalls.md)。
- nginx 必须用自己的 `X-Real-IP` 覆盖客户端自报的地址，否则限速会认错人。`client_max_body_size` 建议 512m（备份包 / 更新包上限）。
- 不要把几 GB 的 `node_modules`、`.next`、整仓或 `main/data/` 打进 git 或拷到服务器。
- 站点对外地址填「设置 → 站点地址」（https，或本机 http://localhost）。

## 从 Halo 迁移（可选）

旧站是 Halo 的话，可以用 `pnpm import:halo` 把备份导进来（文章、瞬间、自定义页面，以及正文里的图片）：

1. 用 `decode_backup.py` 把 Halo 备份解成 `decoded/` 目录（含 `articles/`、`moments/`、`upload/`）。
2. 先预览，什么都不改：`pnpm import:halo --dir <decoded 目录>`；想复核转换出来的正文就加 `--dump <目录>`。
3. 确认无误再加 `--apply` 真正导入，然后 `pm2 restart myblog`（导入直接写库，重启让前台立刻更新）。
4. 导入是幂等的，可以重复跑：图片按内容 hash 去重、文章按 slug、瞬间按内容+时间判重。

细节（映射规则、图片落到哪、哪些东西不导、已知取舍）见 [halo-import-spec.md](halo-import-spec.md)。注意两点：

- 瞬间按**原来的发布时间**入库，所以「瞬间可见范围」的全局可见期如果是"最近 N 天"，一年前的老瞬间会被判过期、前台看不到 → 改成永久。
- 旧正文里的内联样式（居中、缩进、灰色说明文字）不会带过来；要保留原缩进用 `--keep-indent`。

## 不要做

- 生产跑 `pnpm db:seed`
- 把更新包当备份，或把备份包当程序更新
- 手解备份 tar、直接拷 `blog.db`
- 把 `.env`、半钥、`data/` 提交仓库或打进更新包
- pm2 cluster 多进程写同一个 SQLite
- 自定义模块代码复制到评论或文章正文链路
- 共享 COS 桶给别的网站再用「清空 / 删除」类操作
